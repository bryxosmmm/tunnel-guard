# TunnelGuard

**MISIS Loss Volos · Лидеры цифровой трансформации 2026 · Задача № 5, Московский транспорт**

Обнаружение посторонних объектов в тоннеле метро по последовательности облаков
3D-лидара. Алгоритм не требует заранее заданных классов объектов или обученных
весов: восстанавливает геометрию пути, выделяет наблюдаемые объекты, сопровождает
их и раздельно подтверждает присутствие и пересечение опорного контура.

На выходе — наблюдаемые границы и ID объекта, продольная дистанция, статус
подтверждения, качество геометрии и причины неопределённости.
Это исследовательский прототип, **не сертифицированная система предупреждения
столкновений**. Отсутствие обнаружения не означает доказанно свободный путь.

## 1. Локальная установка

Поддерживаемый путь: Python 3.10–3.12, Linux x86-64 или macOS; текущая локальная
проверка выполнена на Apple M3 / Python 3.12. Нужен компилятор C++17:
`build-essential` и `python3-dev` на Ubuntu либо Xcode Command Line Tools на macOS.
Для обычной обработки bag-файлов **не нужны ROS, Docker, GPU или модельные веса**.

```sh
git clone --branch main https://github.com/bryxosmmm/tunnel-guard.git
cd tunnel-guard
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
python setup.py build_ext --inplace
```

Альтернатива с установленным [uv](https://docs.astral.sh/uv/):

```sh
uv sync --locked
uv run python setup.py build_ext --inplace
```

C++-расширение обязательно. Сборка выполняется локально; готовая библиотека
с чужого компьютера не требуется. Первый install использует сеть для зависимостей;
сам детектор после установки работает локально. CUDA — отдельный необязательный
режим, инструкции сборки находятся в `docs/NATIVE_INTEGRATION.md`.

## 2. Исходные данные

Записи организатора распространяются отдельно и **не включены в Git**.
Распакуйте предоставленные ROS 2 bags в следующую структуру:

```text
data/sourcecraft_subset/for_hackathon/
  doubleT_obstacle/       # metadata.yaml и соответствующие *.db3
  doubleT_platform/
  roundT_doubleT/
  roundT_pressureGate_roundT/
  roundT_squareT_pressureGate_squareT/
  squareT_platform_squareT_switch/
data/cloud_with_fake_obj/ # отдельная организаторская запись со вставками
```

Для короткого запуска ниже достаточно `doubleT_obstacle`. Другую запись можно
указать в копии JSON-рецепта через `bags[].path` и, при необходимости, `bags[].topic`.
Путь задаётся к каталогу с `metadata.yaml`, а не к отдельному `.db3`.

## 3. Запуск основного детектора

**Основной профиль сохраняет KISS-ICP и полноценную оценку 3D-преобразования.**
Все пороги детекции находятся в `configs/detector.json`.

```sh
.venv/bin/python -m tunnel_guard.run --experiment configs/submission-smoke.json
```

Команда обрабатывает первые восемь последовательных кадров реальной записи,
без прореживания входного потока. Выход: `build/submission-smoke/`.
Для полной записи скопируйте рецепт, задайте `max_frames: null` и новый `output`.

Рецепт содержит пути к данным и конфигурации, seed **20260915**, число кадров,
настройки потоков и каталог результата. `thread_environment` применяется
запуском до повторной инициализации численных библиотек. Не меняйте пороги после
просмотра контрольных результатов.

**Каталог результата должен быть новым:** программа не перезаписывает прежние
эксперименты. Для повторного запуска измените `output` в копии рецепта.

### Необязательный быстрый профиль

```sh
.venv/bin/python -m tunnel_guard.run --experiment configs/fast-profile-smoke.json
```

Используется `configs/detector-fast-profile.json`; основной конфиг не изменяется.
Для полного фиксированного набора из 3998 кадров:

```sh
.venv/bin/python -m tunnel_guard.run --experiment configs/fast-profile-evaluation.json
```

Этот режим оценивает только **положительное продольное перемещение** по профилю
боковых отражений. Боковое/вертикальное движение и вращения не оцениваются;
небольшой residual не гарантирует их отсутствия. Сохранены исходные проверки
3D-совмещения, геометрия, сегментация и пороги подтверждения. Режим явно
экспериментальный: [ограничения и происхождение метода](docs/FAST_MOTION.md).

Оценка локализации на сохранённых результатах не запускает детектор повторно:

```sh
.venv/bin/python -m tunnel_guard.evaluate \
  --run build/fast-profile-evaluation \
  --annotations annotations/doubleT-obstacle-person-crossing.json \
  --output build/fast-profile-evaluation/person-evaluation.json
```

Оценщик читает и `.jsonl`, и `.jsonl.gz`; временные журналы не считаются предсказаниями.

## 4. Что сохраняется

В каталоге запуска находятся:

- `<bag-name>.jsonl` или `.jsonl.gz` — решения по каждому кадру и объекту;
- `summary.json` — число кадров, статусы и распределения времени;
- `detector.json`, `experiment.json` — точные параметры запуска;
- `manifest.json` и `source/` — версии зависимостей, хеши и исходники;
- `<bag-name>-timing.jsonl` — измерения стадий обработки;
- при явно включённой диагностике — массивы точек и их происхождение.

`presence_confirmed` означает подтверждённое присутствие компонента;
`intersection_confirmed` — подтверждение пересечения **опорного контура**.
Это разные состояния. Размер bbox описывает наблюдаемую поддержку, не полный
амодальный объём объекта. Расстояние — продольная координата в системе обработки,
не путь по кривой и не расстояние от передней точки вагона.

## 5. Docker и ROS 2

В корне находится `Dockerfile` для ROS 2 Humble / Ubuntu 22.04:

```sh
docker build --platform linux/amd64 -t tunnel-guard:submission .
```

Команды запуска контейнера, подачи `PointCloud2`, воспроизведения bag и просмотра
выходных тем приведены в [инструкции по ТЗ](docs/DEPLOYMENT_TZ.md).
Обычный образ собирает CPU C++-режим. На Apple Silicon Linux/AMD64 работает под
эмуляцией: её скорость не характеризует целевой стенд.

## Проверенные результаты и границы

- Один предварительно размеченный эпизод человека: **99/105** совпавших объектных
  кадров при IoU ≥ 0,25. Шесть промахов сохраняются; это не общий recall и не precision.
- Сравнение прежнего ICP и быстрого экспериментального режима: **2488 реальных +
  1510 синтетических кадров**. Совпадения человека сохранились; подтверждения
  пересечения вставленных объектов — **277 → 323** пар «кадр–событие», без потери
  прежних подтверждений пересечения. Пять прежних подтверждений присутствия
  потеряны; разбор показал перенос посторонней истории. Сырой критерий приёмки
  не переписан, профиль не стал основным.
- Прежняя отдельная проверка Ryzen 7 7800X3D + RTX 5090: p95 обработки
  **109,5–149,7 мс** по шести реальным записям. Это не измерение на целевом
  i7-9700E + RTX 4070 Ti SUPER и не полная задержка до отображения.
- Синтетические вставки, повторные кадры одного человека и неполная разметка
  не устанавливают полевую безопасность или частоту ложных тревог.

## Зависимости и воспроизводимость

Python, NumPy, SciPy, Open3D, KISS-ICP, rosbags, threadpoolctl; собственные
C++17-ядра, необязательный CUDA backend, ROS 2 и браузерный просмотрщик.
Версии задаются в `pyproject.toml` / `uv.lock`, контейнерные — в
`docker/constraints.txt`. Лицензии сторонних компонентов сохранены рядом с ними.
Общая лицензия на перераспространение всего проекта не объявлена.

Проверка изменений выполняется реальными запусками детектора и отдельной оценкой
сохранённых результатов. Автоматизированные тестовые наборы проект не использует.
Не коммитьте исходные записи, учётные данные и локальные каталоги `build/`.
