# Итерация 2026-09-16: расстояние по точкам пересечения

## Что сделано и почему

Продолжена текущая реализация после merge, ревизия `3a221cf`; исходное рабочее дерево было чистым. Учтён добавленный в `f47ebd3` фильтр поддержанных поверхностей Open3D. Он включён в обоих вариантах. Deskew выключен, пороги и алгоритмы сегментации/сопровождения не менялись. Commit/push не выполнялись.

**Единственное изменение поведения:** выбор точек для расстояния. На реальном кадре 25 подтверждённый кластер начинается в **12.537 м**, но точки, обосновывающие пересечение контура, начинаются только в **14.308 м**. Раньше сообщался минимум всего кластера, включая его часть вне контура. Теперь экспериментальный режим сообщает минимум точек пересечения, сохраняя весь кластер и его bbox. Это исправление определения расстояния, **не увеличение дальности обнаружения** и не установление истинной опасности этого объекта.

Место изменения: `tunnel_guard/detector.py::cluster_candidates`. Параметр `obstacle_distance_mode`:

- `cluster_min_x` — исходное поведение, значение по умолчанию;
- `envelope_support_min_x` — для `intersecting` используются текущие точки `core`; для `unresolved` — точки номинального пересечения без достаточной поддержки геометрии; для `adjacent` остаётся минимум всего кластера.

Новый вариант задан отдельно в `configs/detector-envelope-distance.json`. `distance_method`, `distance_support_point`, `distance_support_points` показывают основание числа. `cluster_nearest_x_m` сохранён. Сортировка перед сопоставлением остаётся по старому минимуму кластера, поэтому новая величина не переставляет кандидатов. Начало отсчёта — плоскость x=0 настроенной локальной системы; это продольная координата, не длина вдоль пути и не расстояние от бампера. Минимум точки-представителя после вокселизации по-прежнему чувствителен к выбросам.

## Фиксированный набор и разметка

До выбора изменения зафиксирован `configs/iteration-episodes.json`: **весь `doubleT_obstacle`, кадры 0–200**, every=1, один Detector от начала записи. Между первым и последним header timestamp — 20.400 с. Прогрева на отдельном размеченном кадре нет. Оба варианта обработали все 201 сообщение, без дублей и пропусков runner. Вход — только текущие/прошлые измерения; аннотации читает отдельный offline-анализатор, не детектор.

Найдены пять исходных наблюдений в `annotations/sourcecraft-provisional.json` и ранее созданный одно-кадровый **производный** файл `build/audit-prefix-annotations.json`. Новых независимых аннотаций нет. Это один предварительно выделенный объект, а не пять событий. Явных timestamps в аннотации нет: они сопоставлены с реальными acquisition timestamps кадров и сохранены в JSON-отчёте. Bbox интерпретируются в существующей преобразованной локальной системе (x=-rawY, y=rawX, z=rawZ); новая калибровка не вводилась. Extrinsics и идентичность объекта человеком не подтверждены.

Проверенных отрицательных интервалов нет. Остальные bags не объявлялись пустыми по названию. Доказанного пропуска размеченной структуры или ложной тревоги в этой итерации не установлено.

## Куда действительно проходят точки

Числа ниже — **поддержка внутри предварительного bbox**, не доказанная семантическая принадлежность каждой точки предмету.

| Кадр | Валидные XYZ → после range/ICP/crop | После geometry voxel | Context до → после surface filter | В основном кандидате внутри bbox | IoU до / после |
|---:|---:|---:|---:|---:|---:|
| 0 | 998 → 998 | 386 | 383 → 383 | 383 | .2856 / .2856 |
| 50 | 1006 → 1006 | 387 | 385 → 385 | 383 | .2886 / .2886 |
| 100 | 1009 → 1009 | 387 | 385 → 385 | 384 | .2794 / .2794 |
| 150 | 996 → 996 | 384 | 382 → 382 | 382 | .2748 / .2748 |
| 200 | 991 → 991 | 382 | 379 → 379 | 379 | .2842 / .2842 |

Все пять основных кандидатов подтверждены `immediate_geometry`, но имеют отношение **adjacent**. Геометрия пути доступна, основная структура не исчезает в surface filter. На кадре 50 ещё две точки внутри bbox образуют слабую компоненту без поддержки пересечения и отбрасываются; на кадре 100 одна отдельная точка отбрасывается по `weak_min_voxels`. Это реальные потери отражений, но не пропуск основного объекта и не доказательство, что отброшенные точки принадлежат ему. Порог не снижался.

Сохранены точки на этапах, метки компонент и конкретные причины `below_weak_min_voxels`, `below_min_extent`, `weak_without_envelope_support`. `pipeline` отличает `not_run` от `ran` с нулём результатов. На этих эпизодах geometry/segmentation действительно выполнялись. `trace_analysis` показывает связь компоненты с track_id и подтверждением, а не выводит причину из конечного bbox.

Остаётся неоднозначность: bbox основного кандидата доходит по z примерно до 2.2–2.36 м при верхней границе предварительной аннотации 0.65 м. Нельзя без проверки человеком решить, что неверно: разделение объектов, границы аннотации или их физическая интерпретация. Track ID также меняется с 41 на 2807 к кадру 200; независимым событием это не считается. Причина смены ID в этой итерации не устанавливалась.

## Воспроизведение

Из корня репозитория, после распаковки `doubleT_obstacle` в путь из конфига. Уже существующие output directories не удаляйте: для повторения скопируйте recipe и измените `output`.

```sh
UV_PROJECT_ENVIRONMENT=.venv-iteration UV_HTTP_TIMEOUT=180 uv sync --locked --python 3.12
.venv-iteration/bin/python -m tunnel_guard.run --experiment configs/iteration-episodes.json
.venv-iteration/bin/python -m tunnel_guard.run --experiment configs/iteration-envelope-distance.json
.venv-iteration/bin/python -m tunnel_guard.trace_analysis \
  --run build/iteration-envelope-distance --compare-to build/iteration-baseline \
  --annotations annotations/sourcecraft-provisional.json \
  --output build/iteration-envelope-distance/support-analysis.json
# Эта команда evaluate выполнена для обоих run directories:
.venv-iteration/bin/python -m tunnel_guard.evaluate \
  --run build/iteration-envelope-distance --annotations annotations/sourcecraft-provisional.json \
  --output build/iteration-envelope-distance/localization.json
MPLCONFIGDIR=/private/tmp/tunnel-guard-matplotlib .venv-iteration/bin/python -m tunnel_guard.visualization \
  --before build/iteration-baseline --after build/iteration-envelope-distance \
  --cases configs/iteration-visual-cases.json --output build/iteration-comparison
```

Дополнительно выполнен реальный двухкадровый запуск неизменённой ревизии из сохранённого source snapshot: статусы, bbox, расстояния, hits и ID совпали с первыми двумя кадрами инструментированного baseline. Автотесты, synthetic stress и обучение не запускались. `git diff --check` выполнен.
