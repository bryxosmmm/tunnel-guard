# Экспериментальный продольный профиль движения

**Не используется по умолчанию.** `configs/detector.json` сохраняет KISS-ICP.
Быстрый профиль выбирается только через `configs/detector-fast-profile.json`.

## Запуск

Из корня проекта после установки по [README](../README.md):

```sh
.venv/bin/python -m tunnel_guard.run --experiment configs/fast-profile-smoke.json
.venv/bin/python -m tunnel_guard.run --experiment configs/fast-profile-evaluation.json
```

Первая команда обрабатывает восемь реальных кадров, вторая — шесть реальных
записей и организаторскую запись со вставками: **2488 + 1510 кадров**.
Данные берутся из `data/`, не скачиваются программой. Для повторного запуска
нужно новое значение `output`. Seed — **20260915**. Среда потоков задана в рецепте,
`query_workers=8`, `odometry_threads=1`, backend CPU. Полный журнал исследования
на 11 271 дополнительных сканах этим рецептом не воспроизводится.

## Что изменено

Вместо полной регистрации в локальной карте оценивается сдвиг продольного
профиля боковых отражений. Текущая геометрия пути вычисляется один раз до
оценки движения; далее используется тем же детектором без повторного построения.
Сохраняются KISS-препроцессинг и вокселизация, исходные residual/overlap-проверки,
оценка вырожденности, сегментация, сопровождение, контур и пороги подтверждения.

Параметры метода явно записаны в `profile_motion` конфигурации:

- продольный профиль: 6–90 м, шаг 0,1 м;
- боковая полоса: 1,6 < |lateral| < 4,5 м;
- высота над локальной системой пути: 0,3–4,0 м;
- вычитание скользящего среднего по 21 ячейке и нормировка по квадратному корню
  локального счёта с единичной добавкой;
- сглаживание ядром `[0.25, 0.5, 0.25]` и нормировка профиля;
- нормированная корреляция перекрывающихся частей, неотрицательный поиск сдвига;
- слабый prior скорости из последних пяти шагов; медиана скорости доступна после
  трёх измерений; параболическое уточнение внутреннего максимума;
- максимальная скорость поиска 25 м/с, минимальное окно поиска 4,5 м;
- разрыв цепочки профиля при недопустимом интервале; общий сброс детектора при
  разрыве acquisition timestamps сохраняет обычные правила основного профиля.

Нет адаптивного изменения порогов детекции, удаления неудобных точек, обучения
на контрольных событиях или фонового «доказательства безопасности» по проезду.

## Существенные ограничения

Оценивается **только положительное перемещение X**. Перемещения Y/Z и углы
roll/pitch/yaw не оцениваются; обратный ход не моделируется. Повторяющиеся элементы
тоннеля могут создавать ложные максимумы корреляции. Малый 3D-residual не доказывает
отсутствие бокового движения, вращения или ошибки в продольной регистрации.

В `motion` результата явно записываются `estimator: longitudinal_profile` и
`unestimated_degrees_of_freedom`. Первая пара без предыдущего профиля и невалидная
геометрия не получают валидного движения. Конфигурация запрещает deskew,
`overlap_motion_geometry`, пространственный/кадровый пропуск построения фона.
Ковариация остаётся прежней эвристикой, а не новой калиброванной оценкой.

повод задним числом изменить критерий приёмки. **Сырой критерий не пройден**;
неоценённые степени свободы дополнительно не позволяют сделать профиль основным.

## Происхождение

Идея и численный рецепт продольной корреляции исследованы по `adapt.py` из
[EhimenNathan/tunnelguard-lct2026](https://github.com/EhimenNathan/tunnelguard-lct2026),
ревизия `2569926368276a1af6768a39584e54d6f4733312`.
SHA-256 исследованного файла:
`55c0b104ac1c6920a839ff4f8ad914cd2524ddb9944271dfa4fbd035b062f755`.
Авторство этой идеи не приписывается нашей команде. Архивная абляция запускала
оригинальный оценщик; поставляемый `profile_motion.py` реализует только описанные
математические операции и состояние движения с явной конфигурацией.

Сторонний полный детектор, файлы его исходников, веса, классификатор и адаптация
порога в сдаваемый профиль не включены. Загрузка чужого репозитория во время
запуска не требуется. Это **не воспроизведение полного решения другой команды**
и не перенос результатов её модели на нашу систему.
