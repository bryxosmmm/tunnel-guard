## Замечания перед интеграцией

Ссылки на строки ниже относятся к архиву проверенной ветки в
`build/review-gerasimov-20260919/source/`, а не к текущим файлам нашей ветки.

### P1 — выключение prefetch делает запись пустой

`tunnel_guard/io.py:47–48`, `prefetch`. Функция содержит `yield`, поэтому
`return iter(iterable)` завершает генератор, не передавая ни одного скана.
Реальный запуск CLI с `prefetch_depth: 0` завершился кодом 1:
`ValueError: No scans processed from .../doubleT_obstacle`.
Нужен `yield from iterable` и затем `return`. Это также блокирует честное сравнение
режимов чтения на одном и том же HEAD без изменения исходников.

### P1 — расширенный коридор повторно обрезается

`tunnel_guard/detector.py:532–545`, `Detector.process`.
Первый фильтр допускает `|y-offset| < base+|offset|`, а второй ограничивает
`|y| < base+max(|offset|)`. Эти интервалы не эквивалентны.
Например, при base=8 и offset=10 первый допускает y от −8 до 28,
второй — только от −18 до 18. Часть намеренно сохранённых точек опять теряется.
Обе реализации crop_voxels получают этот предел, поэтому проблема не только в C++.
Нужно убрать повторное боковое ограничение либо вычислить предел по реальному subset.
Это статический вывод из условий; количество потерянных реальных отражений не измерено.

### P1 — ковариация продолжения кривой неполная

`tunnel_guard/geometry.py:520–525,545`, `_continuation` и `path`; аналогично C++.
Для y(d)=a*d+b*d² дисперсия содержит не только d² Var(a)+d⁴ Var(b),
но и **2*d³ Cov(a,b)**. Сейчас перекрёстный член отсутствует.
У fit по точкам с одной стороны края Cov(a,b) обычно ненулевая; при продолжении
наружу отброшенный вклад положителен. Получается заниженная неопределённость
именно там, где она участвует в решении о допустимости габарита.
Нужно переносить полную матрицу ковариации. Это необходимая поправка, но она сама
не устраняет корреляцию перекрывающихся окон, ошибку крайнего anchor и ошибку модели.
Называть итог калиброванной вероятностной границей пока нельзя.

### P2 — боковой объект в синтетике меняет размер вместо положения

`tunnel_guard/curved_stress.py:118`, `object_on_arc`.
`lateral_m` добавляется к половине продольного размера; центр остаётся на оси пути.
Нужно смещать центр вдоль локальной нормали, сохраняя размеры.
Заявленная панель с объектом на оси не опровергается этой ошибкой, но ненулевые
боковые смещения сейчас не проверяют препятствия рядом с путём.
Дополнительно: `object_reported` учитывает любой пересекающийся bbox, без требования
подтверждённого пересечения габарита. 12→16/24 означает наличие кандидата, не 16
подтверждённых опасных препятствий. `union_coverage` использует решётку объёма bbox,
а не реальные точки отражений; подпись про visible support неточна.

### P2 — завершение фонового чтения может оставить поток заблокированным

`tunnel_guard/io.py:65,68`, `prefetch.produce`.
Публикация исключения и завершающего маркера вызывает блокирующий `queue.put`
без таймаута. При полной очереди и закрытии потребителя выставленный `stop`
не освобождает такой вызов. Нужна остановимая отправка и контролируемое завершение.
Это статически найденная гонка; обычный успешный replay её не воспроизводит.

## Что полезно

- Параллельное чтение следующего скана отделено от последовательного детектора.
  Чтение вперёд само по себе не означает использования будущих измерений в решении.
- Продолжение по оценённой кривизне разумнее фиксированной касательной там, где
  кривизна действительно наблюдаема. Он сохранил ограничения по неопределённости.
- Обнаружена реальная архитектурная проблема фиксированного sensor-axis crop.
- Отрицательные результаты исследований сохранены. Однако неудача нескольких
  оценивателей не доказывает математическую невозможность других методов.
- Эти изменения прежде всего про горизонтальный путь; они не устраняют обнаруженное
  нами смещение оценки высоты головок и не заменяют полноценную проверку local_3d.

## Собственные запуски

Собрана отдельная нативная библиотека проверенной ветки. На каждой ревизии выполнены
первые 30 сканов doubleT_obstacle, doubleT_platform и roundT_doubleT: **90+90 кадров**.
Конфиг каждой ветки — её detector-native.json; наша ветка использует последовательное
чтение, ветка Герасимова — depth=1. Это сравнение итоговых вариантов, не изолированная
оценка ускорения от prefetch. По одному последовательному прогону, без повторов;
разогрев и фоновые нагрузки не контролировались. Wall time включает старт.

| Запись | Медиана обработки, наша→его, мс | Медиана чтение+обработка, мс | Wall / кадр, мс |
|---|---:|---:|---:|
| doubleT_obstacle | 157.6→174.8 | 195.3→176.2 | 279.5→216.5 |
| doubleT_platform | 129.4→139.1 | 142.8→140.2 | 155.3→148.5 |
| roundT_doubleT | 131.8→144.8 | 145.6→146.2 | 153.2→158.6 |

Общее ускорение на всех записях не подтверждено. Уменьшение ожидания чтения полезно,
но новая геометрия и диагностика добавляют работу; 10 Гц здесь не достигнуты.
Это офлайн-время, не возраст решения относительно измерения датчика.

Идентичности измерений совпали на всех 90 парах. Число наблюдений подтверждённых
пересечений осталось 22/0/0. На obstacle один статус unresolved стал candidate;
на двух других записях статусы неизменны. Объектные записи меняются — это не
эквивалентная замена только ради скорости. В сохранённых историях объектов
не найдено будущих или повторённых времён измерений. Это не доказательство точности:
независимой исчерпывающей разметки панели нет.

## Воспроизводимость и команды

Артефакты: `build/review-gerasimov-20260919/`; компактные результаты:
`results/gerasimov-review-20260919.json`.
Конфиги baseline.json, head.json, prefetch-off.json содержат абсолютные пути,
seed, выходной каталог и фиксированную панель. Каждый runner сохранил код и конфиг.
Архив не имеет собственной .git, поэтому поле git_revision runner может указывать
на внешний репозиторий. Истинные ревизии явно записаны в provenance.json и результатах.

Выполнено из корня, кроме отмеченных команд:

```sh
git fetch origin
git archive origin/experiments/gerasimov | tar -x -C build/review-gerasimov-20260919/source
.venv-iteration/bin/python -m tunnel_guard.run --experiment build/review-gerasimov-20260919/baseline.json
```

Из каталога source, абсолютным Python текущего .venv-iteration:

```sh
python setup.py build_ext --inplace
python -m tunnel_guard.run --experiment ../prefetch-off.json
python -m tunnel_guard.run --experiment ../head.json
```

prefetch-off завершился с ожидаемо зафиксированной ошибкой, остальные запуски — 0.
Сравнение выполнено чтением записанных JSONL, без автоматических тестов.
Первоначальный вызов сборки с ошибочным относительным путём Python завершился 127;
повтор с абсолютным путём собрал библиотеку успешно.
