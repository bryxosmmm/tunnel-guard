# TunnelGuard: архитектура и контракт результата

Точка входа проекта и локальный запуск — [README](../README.md).
По умолчанию используется `configs/detector.json` с KISS-ICP; быстрый
`configs/detector-fast-profile.json` выбирается явно и имеет отдельные ограничения.

## Назначение

На последовательности лидарных измерений найти наблюдаемые объекты без заранее
заданного списка классов, оценить их положение относительно рельсового пути и
передать измеренную поддержку решения. Это геометрическая система восприятия,
а не обученный классификатор и не модуль автономного торможения.

## Обработка одного измерения

1. **Вход и время.** `io.py` читает ROS 2 bags напрямую через rosbags, декодирует
   PointCloud2 по описанию полей, отбрасывает невалидные XYZ, сохраняет индексы
   исходных возвращений и acquisition timestamps. Повтор сообщения не считается
   независимым наблюдением. Рецепт задаёт систему координат сенсора и преобразование.
2. **Подготовка.** Фильтрация по настроенному диапазону и выбор представителей
   вокселей уменьшают избыточность. Пороговые расстояния и плотности заданы в JSON,
   не подбираются по названию записи. Выборка для отображения не меняет решения.
3. **Движение.** KISS-ICP регистрирует скан относительно локальной карты. Отдельно
   измеряются overlap, nearest-neighbour residual и вырожденность геометрической
   поддержки перемещений. Малый residual не доказывает правильность всех компонент
   позы; ковариация эвристическая, не откалиброванная вероятность безопасности.
4. **Геометрия пути.** `geometry.py` оценивает основание, локальный профиль,
   измеренную поддержку пары рельсов, осевую и неопределённость продолжения.
   Основание и головки рельсов различаются. Номинальная колея — 1,52 м;
   наличие двух полос само по себе недостаточно для признания их рельсами.
5. **Наблюдаемый фон.** `background.py` строит поддержанные точками локальные
   плоскости стен/потолка и проверяет нормали. Фоновая модель не распространяется
   произвольно через ненаблюдаемые участки; выступающая поддержка защищается.
   Неподвижность объекта не является основанием удалить его как фон.
6. **Компоненты.** `segmentation.py` строит взаимный граф адаптивных окрестностей.
   Радиус и требуемая плотность зависят от дальности; плотные ядра не объединяются
   только тонкой цепочкой граничных точек. Слабая поддержка сохраняется как гипотеза,
   а не превращается автоматически в подтверждённую опасность.
7. **Сопровождение.** `detector.py` предсказывает положение/скорость, использует
   неопределённость, согласованность размеров и глобальное линейное назначение.
   История ограничена по времени; неподтверждённая поза не используется для
   произвольного накопления пространственной поддержки.
8. **Подтверждение.** Раздельно проверяются присутствие компонента, положение его
   собственных отражений относительно опорного контура и повторная поддержка
   пересечения. Большой объект рядом с контуром не подтверждает вторжение только
   числом точек вне контура. При отклонённом движении отдельный локальный механизм
   требует повторяемой измеренной формы, а не отвергнутого преобразования.

```text
PointCloud2 / ROS bag
        |
декодирование, время, происхождение точек
        |
        +--> движение KISS-ICP ------------------+
        |                                      |
        +--> основание, рельсы, фон --> объекты --+--> сопоставление
                                                     |
                                  присутствие / пересечение / неизвестность
                                                     |
                                       JSONL, ROS 2, просмотр результатов
```

Опорный контур на основе ГОСТ не является независимо проверенной динамической
оболочкой конкретного вагона. Привязка лидара к вагону, кривые, наклон, стрелки
и экстраполяция остаются существенными ограничениями.

## Быстрый профиль

В экспериментальном режиме геометрия текущего скана вычисляется один раз перед
оценкой движения. Продольный профиль боковых отражений сопоставляется с предыдущим;
оценивается только положительное перемещение вдоль X. Далее выполняются прежние
3D-проверки совмещения и тот же конвейер детекции. Режим несовместим с deskew,
перекрытием motion/geometry и повторным использованием фона — конфигурация с
таким сочетанием отклоняется. Полное описание: [FAST_MOTION.md](FAST_MOTION.md).

## Основные поля JSONL

| Поле | Смысл |
|---|---|
| `frame`, `measurement_timestamp_ns`, `source_scan_id` | Идентичность исходного измерения |
| `status`, `health`, `health_reasons` | Состояние обнаружения и пригодность данных |
| `geometry`, `range_observability` | Геометрическая поддержка, неопределённость и доступное покрытие |
| `motion`, `pose` | Оценка движения и результаты её проверки |
| `objects[].track_id` | Идентификатор сопровождения, не класс объекта |
| `objects[].presence_confirmed` | Подтверждённое присутствие измеренного компонента |
| `objects[].path_relation` | Отношение к опорному контуру |
| `objects[].intersection_confirmed` | Достаточность свидетельств пересечения модели контура |
| `nearest_obstacle_m` | Продольная дистанция поддержанного предупреждения; `null` не означает свободный путь |
| `processing_s`, `motion_s` | Измеренная длительность обработки; не возраст результата на экране |

BBox ограничивает текущую наблюдаемую поддержку; амодальная форма не восстановлена.
Дистанция отсчитывается от начала настроенной системы обработки вдоль X, а не от
передней точки вагона и не по дуге пути. Для оценки тормозного запаса нужны скорость,
физическая оболочка вагона, extrinsics, задержки доставки и тормозная модель.

## Интерфейсы и развёртывание

- Offline: `python -m tunnel_guard.run --experiment <recipe.json>`.
- Оценка сохранённых предсказаний: `python -m tunnel_guard.evaluate --help`.
- Просмотрщик: `python -m tunnel_guard.review_viewer --help`.
- Живой ROS 2 / recorded RViz: [ROS2.md](ROS2.md), [DEPLOYMENT_TZ.md](DEPLOYMENT_TZ.md).
- Стандартный Docker-образ — ROS 2 Humble, CPU C++ backend. CUDA собирается отдельно.
- CLI и ROS-адаптер используют один `Detector`; параметры берутся из файлов конфигурации.

Здесь нет обязательного внешнего HTTP API, облачного inference или скачивания
обученных весов. Браузерный интерфейс — локальный просмотр записанных результатов,
не доказательство живой обработки с тем же временем отклика.

## Проверка и ограничения

Каждый запуск сохраняет recipe/config, исходники, хеши, окружение, входные
идентификаторы и результаты. Разметка человека предварительная и неисчерпывающая;
она не позволяет оценить precision. Повторные кадры одного события не являются
независимыми событиями. Организаторские вставки оцениваются отдельно от реальных
эпизодов. Неизвестное покрытие не превращается в «путь свободен».

Известны инфраструктурные тревоги, пропуски локализации и фрагментация треков.
Ни наличие временного подтверждения, ни совпадение CPU/CUDA на фиксированных
данных не доказывают полевую безопасность. Целевые 10 Гц и полная задержка до
предупреждения на стенде ТЗ пока не подтверждены.
